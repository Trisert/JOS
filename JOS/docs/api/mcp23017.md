# MCP23017 I2C expander API

`App/payloads/mcp23017.h` / `mcp23017.c` drives the MCP23017 GPIO expander on
`I2C4` (`I2C_EXT`, PD12/PD13 per OBC V2.0 gerbers). It owns the expander
register state; it does not define which output pin drives which chip-select.

Register map, address range and the output-only pins are from DS20001952 Rev D
(MCP23017/MCP23S17): Table 2-1, Table 3-1 (bank 0), §3.1 and §3.5.1.

## Data shape

- Address: validated 7-bit value in `0x20..0x27` (strap pins A0-A2). There is
  **no default address**. `mcp23017_init()` takes an `unsigned int` and refuses
  an out-of-range value instead of truncating it.
- Register layout: bank 0, the power-on default. `mcp23017_init()` reads address
  `0x05`. That address is IOCON in bank 1 and GPINTENB in bank 0. A set BANK bit
  there makes init refuse.
- `0x0A` is not a valid discriminator: it is OLATA in bank 1.
- Pin numbers: `0..7` = port A, `8..15` = port B. Masks and `uint16_t` values
  use bit `n` for pin `n`. `set_pin` and `get_pin` take an `int` and refuse
  `256` rather than truncating it to `0`.
- `GPA7`/`GPB7` (pins 7 and 15) are **output-only** on the MCP23017. A direction
  mask that requests them as inputs is refused, `get_pin()` refuses them, and
  `read_input()` masks them to 0.

## Operations

| Function | Behaviour |
|---|---|
| `mcp23017_init(addr)` | Probe `0x05`, then read `OLATA`/`OLATB` to seed the output cache (a warm reset keeps the expander latches). Latch the address. A failed init leaves the driver deconfigured: the previous address and cache are dropped before the probe. Return 0 or -1. |
| `mcp23017_close()` | Forget the address and the cached latch. Every operation refuses afterwards. |
| `mcp23017_set_direction(mask)` | 1 = input, 0 = output; writes `IODIRA`/`IODIRB`. Refuses pins 7 or 15 as inputs. |
| `mcp23017_write_output(value)` | Writes `OLATA`/`OLATB`, then updates the cached latch. A failed `OLATA` or `OLATB` write leaves hardware unknown, so the cache is marked unknown and `set_pin` refuses until `mcp23017_write_output()` or `mcp23017_init()` succeeds. |
| `mcp23017_read_input(&value)` | Reads `GPIOA`/`GPIOB`; bits 7 and 15 are masked to 0. Output is written only on success. |
| `mcp23017_set_pin(pin, high)` | Writes only the affected latch byte. Refuses while the cache is unknown. A failed byte write also marks the cache unknown, because the chip may have applied it. |
| `mcp23017_get_pin(pin, &high)` | Reads the corresponding GPIO port bit. Refuses pins 7 and 15. |

All operations return 0 on success and -1 on a null argument, an out-of-range
pin, an uninitialised device, an unknown latch cache, or a failed I2C transfer.
The flight backend calls `HAL_I2C_Mem_Write()` and `HAL_I2C_Mem_Read()` on
`hi2c4` with a bounded 100 ms timeout. Those HAL calls poll I2C status flags,
so no flight task may call the default backend directly until `I2C4` is wired
for interrupt or DMA completion (`AGENTS.md` §4).

Host tests inject a scripted bus through `mcp23017_inject_ops()` and restore a
fail-closed backend with `mcp23017_restore_flight_ops()`
(`HOST_UNIT_TEST` only).

## Contradictions recorded

`docs/api/payloads.md` says `I2C_EXT = I2C4` is unconfirmed, while `JOS.ioc`
pins `Mcu.IP11=I2C4` and PD12/PD13 as `I2C4_SCL/SDA`, and the OBC V2.0 gerbers
route those pins. Per `AGENTS.md` §1 both statements stay on record; this driver
does not resolve the contradiction and uses `hi2c4` only because `main.c`
already initialises it.

## Open question

The strap wiring for A0-A2 is not present in the delivered corpus or the
simulation (`GPIO_expander.zip` routes A0/A1/A2 to header J1 pins 22/21/20,
but no netlist or schematic gives the strap value). The flight caller must
supply the confirmed address; until then `mcp23017_init()` is never called
with a guessed value and the expander stays fail closed. This is tracked in
`TASKS.md` open decision 11 and Gantt task SFW-01.3.
